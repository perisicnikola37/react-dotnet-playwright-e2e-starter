Features

Everything a UI test run needs, inside your app

No separate test server, no CI login for testers. Packages that plug into the app you already have.

Start runs from the browser

Run everything or one category (Smoke, Regression) from a React page. One run at a time, with a timeout, so nobody trips over each other.

Live progress

Queued, running, passed or failed, updated while the run is still going.

Re-run failures

Re-run all, only the failed tests or the same selection with one click.

AllFailedSelection

Failure evidence

Screenshot, page HTML, URL, console, named steps and the Playwright trace.

.png.htmlconsoletrace.zip

Compared to last run

New failures and tests that keep failing are marked automatically.

NEWSTILL FAILINGFIXED

Shareable HTML report

Every run writes a standalone report.html for CI artifacts, tickets or email. No app needed to open it.

Safe by default

Off in Production unless you opt in, works with your authorization, short-lived iframe tokens and sandboxed evidence files.

How it works

From a button click to a full report

The React page calls your API, the API runs your Playwright tests and the dashboard follows the run.

React pagePress Run
ASP.NET CoreStarts the run
Playwright .NETDrives the browser
DashboardLive, then report
Your UI test project · NuGetE2eStarter.Playwright

xUnit v3 base classes: one browser per run, a context and trace per test, failure evidence, live events.

Your ASP.NET Core API · NuGetE2eStarter.AspNetCore

AddAutomatedTests() + MapAutomatedTests(): start, list, re-run and serve runs.

CI or API host · dotnet toolE2eStarter.Reporters

Turns TRX results and evidence into data.json, the dashboard and report.html.

Your React app · npm@perisicnikola37/e2e-starter-react

<AutomatedTestsPage />: start runs, see history and the live dashboard.

Why

Stop digging through CI logs

The same Playwright tests, with the run, the evidence and the report in one place.

Plain test runs

  • Testers need CI access to start a run
  • Failures hide in console logs and zipped artifacts
  • Re-running one failed test means editing a pipeline
  • Sharing a result means sending screenshots by hand

With the dashboard

  • One button in your own app starts a run
  • Screenshot, steps, console and trace next to the error
  • Re-run only the failures with one click
  • One standalone report.html to share
Quick start

Up and running in four steps

Everything installs straight from nuget.org and npm: no tokens, no extra feeds. Do the steps yourself or paste a prompt into your AI assistant. Starting from scratch? Use the template.

.NET 10 SDKNode.js 22+React 18+ASP.NET Core backend
Terminal · MyApp.E2E.csproj · ItemsTests.cs
# Install
dotnet new xunit3 -n MyApp.E2E && cd MyApp.E2E
dotnet add package E2eStarter.Playwright
dotnet add package Microsoft.Testing.Extensions.TrxReport

// global.json: "test": { "runner": "Microsoft.Testing.Platform" }
// MyApp.E2E.csproj: <OutputType>Exe</OutputType>

// Once per test project: shared browser + live progress
[assembly: TestFramework(typeof(LiveProgressTestFramework))]

[CollectionDefinition(UiTestBase.CollectionName)]
public sealed class BrowserCollection : ICollectionFixture<SuiteFixture>;

[Trait(TestCategories.Key, TestCategories.Smoke)]
public sealed class ItemsTests(SuiteFixture suite) : UiTestBase(suite)
{
    [Fact]
    public async Task Adds_an_item()
    {
        Step("Open the items page");
        var items = await new ItemsPage(Page).OpenAsync();

        Step("Add an item");
        await items.AddItemAsync("Review the test plan");
    }
}

# Then copy scripts/run-ci.sh from the repo and point it at this project
Terminal · Program.cs · appsettings.json
# Install (in your ASP.NET Core API)
dotnet add package E2eStarter.AspNetCore

// Program.cs
builder.Services.AddAutomatedTests(
    builder.Configuration.GetSection("AutomatedTests"));
// ...
app.MapAutomatedTests().RequireAuthorization();   // /api/automated-tests

// appsettings.json (WorkingDirectory is where scripts/run-ci.sh lives)
"AutomatedTests": { "WorkingDirectory": "../..", "Title": "My app · UI tests" }
Terminal · App.tsx
# Install
npm install @perisicnikola37/e2e-starter-react

// App.tsx
import { AutomatedTestsPage } from "@perisicnikola37/e2e-starter-react";

<Route path="/automated-tests"
  element={<AutomatedTestsPage categories={["Smoke", "Regression"]} />} />

// The page calls /api/automated-tests on the same origin: proxy it in dev,
// or pass a client with createAutomatedTestsClient({ baseUrl, getAccessToken }).
Run it
# 1. Start your API and your web app, then open
http://localhost:<port>/automated-tests

# 2. Pick a category (Smoke, Regression) and press Run.
#    The dashboard updates live; when the run finishes, re-run only the failed tests.

# Or without the UI, against a running app:
scripts/run-ci.sh out/run1 Smoke

Security

A test-environment feature, locked down

The API runs a command that drives a browser, so the defaults are strict.

Not in Production

Nothing is mapped in Production unless AllowInProduction is true.

Your authorization

RequireAuthorization() protects the API; dashboard routes need a short-lived token.

Sandboxed files

Strict CSP for the dashboard; evidence is served with sandbox, nosniff, no-store.

CSRF guard

Re-runs need an X-Requested-With header from the dashboard.

FAQ

Questions, answered

How do I add a Playwright test dashboard to my React app?

Add E2eStarter.AspNetCore to your ASP.NET Core API, call AddAutomatedTests() and MapAutomatedTests(), then render <AutomatedTestsPage /> on any React route. Testers can start runs, watch them live and open the report from that page.

Does it work with Playwright for Node.js (@playwright/test)?

The runner and reporter are built for Playwright for .NET with xUnit v3. The React page and dashboard only talk to the HTTP endpoints, so another runner can be plugged in, but the starter ships the .NET pieces.

Is it safe to expose the endpoints?

They are disabled in Production unless you set AllowInProduction, can be protected with RequireAuthorization(), the iframe uses short-lived dashboard tokens and evidence files are served with a sandbox Content-Security-Policy.

How do I install it and what are the requirements?

Everything is public on nuget.org and npm: dotnet add package E2eStarter.Playwright / E2eStarter.AspNetCore and npm install @perisicnikola37/e2e-starter-react. No tokens or extra feeds. You need the .NET 10 SDK, Node.js 22+ and a React 18+ app with an ASP.NET Core backend.

Can I share a report without the app running?

Yes. Every run writes a standalone report.html with screenshots, steps, console output and the Playwright trace. Upload it as a CI artifact or send it to anyone.

Can I run the same tests in CI?

Yes. The tests are a normal dotnet test project; the repository includes GitHub Actions workflows that run them and publish the report.

What does it cost?

Nothing. It is open source under the MIT license.
